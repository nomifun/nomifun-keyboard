# NomiFun 原生四键字幕板产品设计

[English](nomifun-native-keyboard.md) | 简体中文

状态：当前唯一产品设计；2026-10-19，Asia/Shanghai。

工程分为 `keyboard` 固件和 `nomifun-desktop` 桌面程序。本文定义产品行为，协议、平台和构建细节由下方技术文档补充。

## 产品定位与范围

四键键盘控制 NomiFun 的原生语音字幕工具。声音来自电脑操作系统的默认或指定麦克风，键盘提供四键事件与 Nomi 状态屏幕。运行链为 Rust/Tauri，随 NomiFun 安装、更新和卸载。

核心流程是：按住 K4，等待青绿色聆听提示后说话 → 松开识别并定稿 → 编辑或用 K2 美化全文 → 在字幕中选择文字并用系统复制快捷键取用。K3 随时取消当前未完成操作，保留此前已定稿正文。流式识别边说边显示临时字幕；云端普通 ASR 在松开后识别。本期不包含自定义系统快捷键、跨应用文字注入、Agent 工作流、键盘板载录音或 USB Audio 麦克风。

支持 Windows、macOS、Linux。主工作台仍保持 880×600 合同，字幕是独立小窗口。其他应用持续保持前台焦点不作为一期验收要求；现有尽量不激活的显示方式继续使用，显式编辑及 K1 的聚焦行为按本文执行。

## 四键职责与正文生命周期

| 按键 | 固定行为 |
| --- | --- |
| K1 | 主程序未运行时启动并显示；主窗后台时显示并聚焦；主窗前台时隐藏到托盘 |
| K2 | 使用配置的无工具文本模型，美化当前完整已定稿正文 |
| K3 | 取消当前准备、录音、识别或美化，撤销待执行动作，保留已定稿正文和字幕窗口；空闲时无副作用 |
| K4 | 按下保存字幕编辑和选区，准备并启动 OS 麦克风；松开停止本段、收齐尾音及识别结果，再提交一次 |

实体键 k1–k4 固定对应 K1–K4，无需校准或自定义映射。K1–K3 消费 click，K4 消费匹配的 down/up，同一手势的 click 不重复启动录音。K1 的窗口切换不打断字幕和后台录音。K2/K3 单键开关只更新主机操作授权，不重置设备按压状态，当前 K4 录音仍由对应松键结束。K4 的物理按住意图独立于上一段识别收尾：收尾中再次按住会等待并在上一段结束后自动启动；等待中松开即撤销，不重放已释放的短按。录音真正建立后只消费一次按住，重复 down/up 不创建额外录音。尚未进入聆听就松开按取消处理。取消、停止、美化、关闭、禁用及重连撤销相应等待；旧稿关闭不把尚未开始的按住带入新稿。

首次录音创建新文档。同稿后续录音按以下规则写入：

- 用户在字幕内定位了光标：插入该位置；明确选中了文字：替换该选区。
- 没有有效定位：直接在正文末尾续接，不因再次录音额外添加换行、空格或其他分隔符。
- 用户或 ASR 返回的空白、CRLF、换行保持原样；供应商流式内部多个分段也直接按顺序拼接。视觉折行由窗口宽度决定，不写入复制结果。

选区以 UTF-16 偏移绑定文档 ID、正文 revision、编辑标识和本次录音，拒绝越界或拆开 emoji 代理对。录音开始后插入位置固定；partial 只作临时预览，不改已定稿正文。停止证明和 ASR final 都齐备后提交一次，空白结果不删除所选原文。完成后光标推进到新内容末尾。

用户可在空闲且系统录音已停止时显式点击正文编辑，支持中文输入法、Unicode、换行和选区，也可保存空正文。修改增加 revision，并成为后续美化和恢复原文的基线；同文保存不重置基线。输入法组合期间及尚未完成的保存按顺序协调，K2/K4 等待当前编辑确认后再使用新全文；K3 取消不依赖编辑保存或模型结果，立即撤销当前未完成操作。保存失败或超时撤销自动动作并保留本轮草稿；关闭、取消、换稿、重连撤销待执行动作，旧应答不能占用新文档的编辑任务。

录音和模型处理中正文只读。K4 不自动全选，也不使字幕整框出现焦点边框；字幕编辑器仍获焦时显示细光标位置提示。完成后仅在当前文档和实际编辑器焦点仍有效、且没有输入法组合时恢复光标，不为恢复位置额外抢焦点。

关闭按钮或字幕获焦时的 Esc 结束本轮：撤销处理与待执行动作，真实停采并成功隐藏后清空正文、原文、候选、光标和全部操作身份。下一次录音是新文档。K3 和工具条取消仅结束未完成操作，保留已定稿正文和窗口；取消段、临时字幕、候选及迟到结果不得写回。K3 取消录音后即便 K4 仍被按住也不自动重录，必须先释放再重新按下。正文和录音默认不落盘，不在重启或下一轮恢复。

## 独立字幕窗口

默认尺寸 720×112、最小 360×80，均为 Tauri 逻辑尺寸。窗口透明，无系统阴影、常驻标题、说明卡片、最大化和最小化入口。默认只有浅粉正文与细描边；全文可选择和滚动。首次位于当前屏幕工作区底部居中，拖动后记忆位置，恢复时按当前工作区、多屏及缩放夹取到可见区域。

正文采用系统 UI 字体，默认 14，设置范围为整数 12–32。字号只影响呈现及光标位置测量，不改变正文、偏移含义、模型输入或复制结果；旧设置缺少该字段时使用默认值。

悬停或窗口内部获得焦点时显示半透明灰色交互底和图标工具条；默认隐藏。工具条提供拖动、停止、取消、美化、恢复原文、置顶、关闭，支持键盘操作。按钮和实体键进入同一 Rust 操作协调器。

焦点在字幕内时，复制使用系统 `Ctrl+C`（macOS 为 `Command+C`），按系统选区语义复制，再由用户在目标应用自行粘贴。未选择文字时不自动改为全文复制，不创建应用级剪贴板命令或跨应用粘贴功能。`Esc` 关闭并清空字幕；输入法组合期间先交给输入法取消组合，不同时关闭窗口。这些快捷键只在字幕获焦时生效，不注册全局快捷键。

状态提示固定在顶部正中，与工具条留出空间，在最小和默认宽度均不重叠。失败采用正文外的简短提示，显式展开才显示详情；诊断统计不拼进正文或复制结果。设置页只呈现本地配置请求、系统输入和本页主动测试的反馈，不重复显示字幕文稿的历史失败。

| 状态 | 表达 | 真实含义 |
| --- | --- | --- |
| 准备 | 琥珀色等待提示 | 等待上一段收尾、编辑/IME 保存、ASR 建连或输入设备启动，尚未确认采集 |
| 聆听 | 青绿色动态音柱与简短提示 | 本次原生输入首个有效非空回调已到达，Actor 确认采集就绪 |
| 收尾/识别 | 紫罗兰色提示 | 正在停采排空，或等待所选 ASR 的完整结果 |
| 错误 | 简短可诊断错误 | 不制造成功状态，保留可恢复正文和操作入口 |

音柱表达采集生命周期，不冒充实际声压或语音活动。全零采样也能证明输入回调已开始，但全零录音不能制造成功识别。准备时即可停止或取消；松键、停止、取消或错误后立即撤去聆听动效，状态消失不替代停采证明。提示不写入正文、模型请求或剪贴板，不播放提示音。

K2 处理中保留原正文，字芯发亮，玫紫贴字光圈与柔和冰蓝外晕平滑呼吸，只绘制一份真实文字。光效局限于字形周围，不显示满窗遮罩或矩形发光框；减少动态效果时保留静态光晕。完整成功后才替换正文，结束或取消恢复默认文字；不为展示动效拖延模型或提交。

## 操作协调与失败语义

| 当前状态 | K2 | K3 | K4 |
| --- | --- | --- | --- |
| 空闲、空正文 | 提示暂无文字 | 无副作用 | 开始新段 |
| 准备中 | 撤销未开始的采集后处理已定稿正文 | 撤销准备和待执行动作 | 松开撤销准备 |
| 正在录音 | 停止本段，等待尾音/final 后美化 | 真实停采并丢弃本段，取消本段 ASR | 松开正常结束本段 |
| 正在收尾/识别 | 记录一次完成后美化意图 | 撤销请求与美化意图，丢弃本段临时结果 | 仍按住则完成后接续；松开撤销等待 |
| 正文就绪 | 美化全文 | 无副作用 | 插入选区或续写 |
| 美化中 | 合并连按，不重复请求 | 取消候选和请求，保留美化前正文 | 等待完成或取消 |

活动录音优先于空正文判断。收尾阶段最多登记一次美化意图，K3 立即撤销，不等待 ASR final 或美化成功。取消不会提交本段、触发新识别、复制或关闭窗口；流式模式已经上传的音频无法回收，但本机会终止会话并拒绝其后续结果。普通模式尚未上传时直接清空缓冲，已提交时取消本地请求或轮询，迟到完成不写入正文。正常松开仍执行所选 ASR；不通过静音阈值猜测用户是否想取消。

美化直接调用原生单次文本转换 API，只传当前全文及美化指令，要求保留原意、事实、人名、数字、日期、代码和专有词。不加载 Agent 会话、技能或项目配置，不自动重试或切换模型；按精确模型声明选择最低可用思考档，输出预算同时受正文大小与模型上限约束。候选在原有文字和光晕中流式临时预览，完整成功才提交。失败、取消、截断保留原文，支持恢复原文。

文档 ID、revision、录音 ID、操作 ID 和激活代次隔离所有回调、编辑任务、模型候选及窗口请求。跨端取消代次作废 UI 编辑保存后排队的动作，保留草稿，迟到保存不能重新启动已取消的美化或录音。取消与关闭按当前文档 ID 接受，同文稿保存造成的 revision 变化不阻断控制；新文档严格隔离，旧取消代次不影响新操作。正文编辑和模型结果仍校验匹配 revision。重复键、取消、重连、窗口重建、旧文档关闭和迟到结果不能重复请求、重复追加或关闭新稿。原生停止失败保留 owner 和可诊断状态，不能以忽略音频或清空 UI 冒充已停止。

## 设置与模型

「设置 → 拓展键盘」集中提供：

- 设备连接、设备标识/串口和固件版本。内部协议握手及 NONE 安全状态由原生服务管理，不作为用户设置。
- “启用 K2–K4”总开关和三个逐键开关。总开关不影响 K1，关闭再开启保留逐键偏好。
- 默认或指定系统麦克风、权限/采集状态、ASR 模式、对应模型、语言、词典和录音测试。
- 文本模型、整段美化指令；字幕置顶、位置重置、打开和字号。
- 登录启动、后台服务状态、退出全部服务。

开关通过原设置路径生效，模型、输入与窗口偏好按设置页保存/撤销。禁用 K2/K3 阻止新的对应硬件动作；禁用 K4 或总开关必须取消当前段、真实停止系统输入，并阻止新录音，保留已定稿正文。总开关同时撤销未完成的硬件动作与待执行美化。浮窗按钮和字幕内系统编辑快捷键仍允许用户显式操作。

ASR 和文本模型复用 NomiFun 现有模型目录、供应商连接和凭据，设置只保存已有模型引用，不建立第二套密钥或模型目录。K2 是无工具文本转换，不创建 AgentSession，不加载技能、MCP 或执行工具。

两种 ASR 模式由用户明确选择，不将流式失败自动改为另一种可能计费的请求：

| 模式 | 采集与提交 | UI/完成条件 |
| --- | --- | --- |
| 流式 | 原生 PCM 增量转换、按供应商真实流式协议上传；停止只发送一次输入结束 | partial 实时预览，final 与停采齐备后结算 |
| 云端普通 ASR | 内存缓冲本段 PCM，真实停采后封装 WAV，经已有文件/异步 ASR 接口提交一次 | 录音时明确“松开后识别”，不制造 partial；只接受完整 Transcript |

普通模式最多 10 分钟，超限停采报错；异步识别沿用同一次提交的 job/context 轮询，不重复上传。取消清空缓冲，不默认保存录音。采集结束可保留时长、电平等诊断统计，不保留声音内容；失败、截断、取消、超时均不落稿。

## 原生音频与准备阶段

主程序枚举并持有唯一 OS 输入流，处理实际采样率、声道和格式，增量转换为 16 kHz 单声道 PCM。原生首个有效非空回调才证明本次采集开始，不能从 K4 down、document recording、`play()` 返回或 ASR partial 推断就绪。

音频启动通过专用短寿命 relay 进入单一 owner，不在共享阻塞池后排队。首回调等待 5 秒，原生驱动/权限等待及 Actor 启动边界为 15 秒；超时取消准入，持有未结束的 owner，继续等待真实停止回执，错误路径不无界 join。

Windows 主程序可在后台预备既有 COM 运行期和设备枚举器，不提前创建或播放麦克风流。StepFun 不强制开启 commit 后二遍纠错，未配置时使用供应商默认关闭；显式配置仍保留，且始终等匹配的完整 completed 才定稿。时间上限均是故障边界，不是固定等待；匿名阶段计时分别记录开麦、停采、配置解析、响应头、首字与完成，不以 UI 状态混算供应商耗时。

ASR 后台预热必须有可取消的任务和开始时间。首次按住 K4 遇到尚未完成的后台预热时，真正取消旧 future，再为本次按住建立独立请求，无须用户松开重按。20 秒绝对期限覆盖排队、配置和连接；Ready 仍须核对期限、文稿、激活代次和当前按住状态。取消、panic、错误、超时都退休任务并释放连接，不能仅忽略结果或让旧任务清除新任务句柄。空闲预热失败只退避重连，不修改正文、编辑/美化任务或已有错误；由用户触发的连接与录音失败保留中文原因和重试指引，并协调真实停采。

正常停止关闭原生流、等待在途回调、交付已采集尾部，再结束流式输入或提交普通 ASR。取消、关闭、禁用、模式/设备切换、锁屏/休眠、输入丢失、设备断开和退出均停止系统采集、撤销待执行动作；恢复需要重新按键。队列按音频时长和等待时间有界，阶段日志仅记录状态、时长、代次及布尔门禁，不记录正文、声音或凭据。

## 设备服务、固件与状态屏幕

轻量 Rust 设备服务在普通主窗和单实例初始化前进入独立模式，唯一持有串口，通过鉴权本机 IPC 发送按键和设备状态。它不持有模型凭据、字幕正文或 OS 录音。无主程序时等待 K1 启动主程序；启动中节流，避免连按启动风暴。服务固定以 k1 接收冷启动请求，不保存键位映射。

主程序准备完成前不接纳 K4；每次连接、服务恢复和休眠恢复均应用 `voice_key:none`，等待真实确认、清除旧手势并等旧按键释放后再 arm。最终协议要求 native v1、系统音源与 NONE 零 session；板载音频帧是显式协议错误，不进入 ASR。设备身份不能仅由通用 VID/PID 或串口名推断。

当前固件源码版本为 `0.3-screen.2`，实物安装版本独立记录在本地私有档案，维护规则见 [DEVICE.md](../../DEVICE.zh.md)。最小 ESP-IDF 固件仅包含四键消抖、严格有界 USB JSON/身份/epoch/租约/NONE/释放门禁，以及必要状态屏幕。组件为 `vk_input`、`vk_usb`、`nk_screen`，不包含板载 I2S/AFE/Opus、LVGL 资源上传、LED、网络、Agent 或 OTA 业务。

NV3007 屏幕为 428×142，显示 Nomi 眼睛、眨眼/呼吸、四键反馈、连接/主程序睡眠和固定的准备、聆听、识别、美化、错误状态，K3 提示为 `CANCEL`。只由主机真实采集状态显示 listening，不显示用户正文。独立屏幕 owner 使用小条带 DMA；屏幕失败独立降级，不能阻断 USB、松键或停采。亮度区分正常和睡眠，按键反馈不代表已经开麦。

普通退出主程序会停止模型和 OS 录音，向设备服务确认 DesktopStopped，设备服务继续等待 K1；“退出全部服务”、安装更新及卸载通过管理端点停止设备服务。安装换文件前必须确认 GUI 停采/退出及串口 owner 释放，失败或超时阻止替换；卸载在停服后清理登录登记，保留用户数据。

固件源码可离线修改和构建；刷写另行绑定实际设备 MAC、镜像 hash、分区、完整原厂备份和恢复路径，没有具体授权不刷写。已刷镜像、私有原始证据、恢复备份及许可证保留；它们不构成旧产品运行路径。

## 平台实现与验证边界

| 范围 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 登录设备服务 | 当前用户 HKCU Run，安装路径与停服清理 | Aqua LaunchAgent，实际 .app 路径和签名身份 | XDG autostart，继承图形会话；AppImage 使用持久路径 |
| USB | COM 枚举、独占、稳定身份 | /dev/cu.*、独占与热插拔 | ttyACM/ttyUSB、udev/uaccess 权限 |
| 输入 | 原生系统输入与权限 | CoreAudio、用途声明与 audio-input entitlement | 当前系统音频服务、默认或指定输入 |
| 主窗/字幕 | 原生窗口显示/隐藏/置顶 | AppKit 主线程窗口操作 | GTK；X11 与 Wayland 合成器路径 |
| 字幕编辑 | WebView2 系统选区复制、IME 和 Esc | WKWebView 的 Command+C、IME 和 Esc | WebKitGTK 的系统选区复制、IME 和 Esc |
| 分发 | NSIS 安装/更新/卸载停服 hook | 签名更新与随包卸载脚本 | deb/rpm 生命周期、AppImage 显式卸载脚本 |

Linux 的 X11、GNOME Wayland、KDE Wayland 使用对应窗口管理与 WebKitGTK 系统剪贴板路径；默认 Wayland 窗口后端为 XWayland，依赖与 udev 规则随发行形式配置。纯 Wayland 无 XWayland 不属于当前窗口后端。

macOS 使用 CoreAudio/AppKit、用户登录服务及签名分发配置，支持 arm64/Intel。原生构建、权限、登录、字幕/编辑/剪贴板、睡眠和安装更新检查在目标 Mac 执行，具体步骤见 NomiFun 技术文档。

## 工程维护

核心回归覆盖文档/操作身份、K3 各阶段取消/迟到结果、真实停采、UTF-16 编辑与 IME、连续正文、字幕内系统选区复制/Esc、设置保存、双 ASR、模型无工具边界、窗口、设备 NONE/Rearm/鉴权/单 owner 和打包生命周期。具体命令见 NomiFun 技术文档；修改 renderer 后执行 `bun run check:desktop-ui-boundary` 及相关检查。

源码、测试和入口保持单一实现。生成日志、运行报告和截图不纳入 Git；原厂恢复材料与私有硬件证据在本机单独保管。产品文档只维护当前行为与技术合同。
