# 操作系统录音与按键输入合同

[English](input-audio.md) | 简体中文

本合同补充[最终产品设计](../design/nomifun-native-keyboard.zh.md)。声音来自电脑默认或用户指定的系统麦克风；设备只提供四键与状态屏幕，永久 NONE，不参与音频采集。

## 录音身份与就绪

K4 down 由 Rust 建立 host 录音/操作 ID，先确认字幕编辑和 UTF-16 插入位置，再准备所选 ASR 与原生输入。匹配的 up 结束同段，click 不重复启动。物理按压具有 Released/Waiting/Consumed 三态，与上一段音频/识别状态分开；忙时保持按住可在前段结算后接续，松开等待即撤销。开始前松开按取消处理，关闭和显式操作不继承尚未开始的按压。所有回调绑定文档 ID、revision、录音 ID、操作 ID 和激活代次。

使用输入的实际采样率、声道、格式，增量转换为 16 kHz 单声道 PCM。默认/指定设备须处理权限、切换、丢失和打开失败，不回退到输出设备或虚拟成功输入。

只有本次原生首个有效非空输入回调证明采集开始；全零数据也能证明回调已到达。不能从 `play()` 返回、K4 down、document recording、ASR partial 或 `audioState=starting` 宣称已聆听。Actor 复核 `handle.input_ready()` 后发布 capturing。准备提示同时覆盖编辑/IME、ASR 连接及原生 starting；只有 capturing 显示青绿色持续聆听动效，准备为琥珀色、收尾/识别为紫罗兰色，统一顶部居中。

原生启动使用专用短寿命 relay，避免共享阻塞池排队；首回调等待 5 秒，原生驱动/权限及 Actor 启动边界为 15 秒。超时关闭准入，保留未结束 owner，继续取消/停采协调。启动错误不无界 join，不丢弃 owner 或伪造停止证明。

ASR 预热由可取消 owned task 管理。首次 K4 遇到未完成的预热时真正取消旧 future/连接，为本次按住创建新准备请求。20 秒绝对期限覆盖排队和连接，完成、panic、取消、超时均单次退休任务。Ready 必须再次核对代次、期限、文档和按住授权，旧任务不得清除新请求或重新开麦。

## 模式与提交

| 模式 | 输入与上传 | 提交正文 |
| --- | --- | --- |
| 实时流式 | 按供应商真实协议增量上传；partial 临时显示 | 原生停采和完整 final 齐备后只提交一次 |
| 云端普通 ASR | 录音时只在内存缓冲；停止回执后封装 PCM16 WAV，提交已有文件/异步 ASR | 完整 Transcript 才结算；Pending 沿原 job/context 轮询，不重复上传 |

普通模式上限 960 万 samples（16 kHz、10 分钟），超限停止并报错；不伪造 partial，不默认保存音频。取消永久关闭本段缓冲准入并清空内容。两模式由设置明确选择，错误不自动跨模式重试。

正常停止关闭原生 stream、等在途回调、交付已采集尾部，再发送唯一流式输入结束或提交一次文件识别。流式结束信号独立于音频队列同步封口，不因等待发送的 future 被取消而丢失；worker 排空封口前的 PCM 后提交一次 EOS/commit，公平处理音频与供应商消息。终态关闭输入准入，下一段不得复用已封口或已退出的会话。显式取消与内部处理故障分别结算，所有终态都清理当前操作并允许新的合法按压恢复。K2 在活动录音时先走该路径，等完整定稿再美化；活动录音优先于空正文判断。

K3 在准备、录音、收尾/识别或美化时取消当前未完成操作，不等待 final，不提交取消段，也不关闭窗口。录音取消真实停止系统输入并丢弃尾部与缓冲；普通 ASR 尚未上传时不再上传，已提交则撤销请求/轮询并拒绝迟到结果。流式已上传部分不能回收，本机取消会话并拒绝后续结果。取消保留此前已定稿正文，撤销待执行美化及等待中的按住意图；K4 仍被按住时须先释放才能开始新段。空闲按 K3 不改变正文或窗口。K4 正常松开仍发起所选识别，不用音量阈值替代显式取消。

停止、取消、关闭、禁用 K4/总开关、切换模式/输入、断开设备、锁屏/休眠和退出进入同一停止协调器。取消丢弃本段，停止失败保留真实状态和 owner；不能仅丢弃音频、停上传或关闭 UI 就宣称已停采。设备 NONE 回执只证明板载采音关闭，不能替代 OS 停采证明。

队列按音频时长与等待时间有界。只保留 samples/nonzero/peak/sum_squares 等统计用于本段时长和电平诊断，不保留声音内容。全零输入明确报错，低音量、缺少语音或缺 final 均不自动推断成功。

## 正文与编辑

有有效字幕光标时插入该位置，明确选区则替换，无定位时直接文末续接。偏移以 UTF-16 绑定本段身份并拒绝越界/半个代理项；开始后固定位置。partial 不修改定稿正文，空白 final 不删除选区。主机不在多次录音或流式供应商分段间注入换行或分隔符，原有 CRLF/空白保留，软折行不进入复制结果。

定稿后光标推进至新文本末尾；仅当前字幕编辑器仍获焦且非 IME 组合时恢复，不新增聚焦调用。K4 不全选或出现整框黑边。关闭清空本轮及光标，新文档不继承旧位置；取消但不关闭保留已定稿正文。迟到编辑、音频、final、模型或窗口应答不得修改新文稿或关闭新窗口。

字幕获焦时保留系统 Ctrl+C / Command+C 选区复制；不绑定硬件复制、不自动全选或自动全文复制。用户在目标应用自行粘贴，不经过 NomiFun 的动作或注入路径。Esc 进入同一关闭路径，真实停采后清空本轮；IME 组合中的 Esc 优先处理组合，不同时关闭窗口。

## 平台与模型边界

Windows 使用原生系统输入；macOS 使用 CoreAudio 并配置用途声明、权限及 audio-input entitlement；Linux 记录实际 ALSA/PulseAudio/PipeWire 与会话权限。原生权限与会话行为在目标平台检查，构建和部署步骤见 NomiFun 技术文档。

ASR、文本模型、语言、词典与凭据复用现有 NomiFun 配置，设备服务不持有音频或凭据。K2 只发送完整正文和美化指令，不创建 AgentSession、装载技能/MCP 或调用工具。阶段日志只记录状态、计时、代次、错误类别与布尔门禁，不记录正文、录音或凭据。失败消息与采样时长/电平统计分离；字幕只呈现简短可恢复状态，详情按需展开。

K2 使用原生单次文本转换 API，共享连接池，不加载项目配置、不自动重试或切换模型；按精确模型能力使用最低可用思考档，并限制输出预算。候选可流式临时显示，完整协议成功后才替换正文，失败或取消恢复原文。StepFun 流式 ASR 不强制开启 commit 后二遍纠错，未配置时采用官方默认关闭；无论是否开启，仍须匹配完整 completed 才提交。Windows 可提前初始化 COM 枚举器以减少首次准备，但不提前开麦或放宽真实停止证明。
